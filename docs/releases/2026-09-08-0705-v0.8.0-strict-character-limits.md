# 0.8.0 — strict character limits

**Contracts package:** `0.8.0`

**Template contract revision:** `4` (was `3`)

**Compatibility:** coordinated consumer update and template re-import required

**Release status:** prepared locally; not published

## Why

Estimated rendered-line capacity remains useful, but it is not an exact strict
character bound. Text and table generation again require explicit aggregate and
per-item character limits in addition to the existing line and item limits.

## Contract behavior

Text components require four additional positive-integer tags:

- `efficio_min_chars` and `efficio_max_chars` bound the combined length of all
  generated items;
- `efficio_min_chars_per_item` and `efficio_max_chars_per_item` become JSON
  Schema `minLength` and `maxLength` for every generated item.

Rendered table cells use the same unprefixed fields. Each minimum/maximum pair
is optional, but a supplied pair must be complete, ordered, and feasible with
the configured item bounds. Existing `max_lines`,
`estimated_chars_per_line`, `min_items`, `max_items`, and `target_items`
behavior is unchanged.

V2 prompt schemas expose per-item bounds directly. Aggregate bounds remain in
trusted normalization metadata because JSON Schema cannot sum array string
lengths; semantic validation produces deterministic repair findings and
instructions for aggregate violations. Data-bound submission contracts remain
limit-free.

## Migration

Revision `3 -> 4` derives conservative defaults from current line capacity:

```text
min_chars = 1
max_chars = max_lines * estimated_chars_per_line
min_chars_per_item = 1
max_chars_per_item = max_chars
```

All text components are migrated. A rendered table cell is migrated only when
it already has complete line-capacity fields. Table cells without line capacity
remain valid without character limits. The migration is append-only, so older
templates still traverse every adjacent revision in order.

## Consumer work

- Template Editor: consume `0.8.0`, expose the four text fields and optional
  table-cell pairs, and apply revision-4 patches to both host tags and reusable
  component-template metadata.
- Slide Generator: pin the verified `0.8.0` release, bump its contract-driven
  re-import tracker, drain incompatible V2 drafts, and re-import V2 templates.
- Other clients: continue using the emitted schemas and repair instructions;
  no content envelope shape changes.
