# 0.9.0 — selection fill

Release target: `0.9.0`. Template contract revision remains `4`.

Adds an opt-in binary mode to `categorical_fill` so a set of items needs one
selection instruction and one `selected_ids` array, not a case decision per item.
Existing classification components and templates keep their current behavior.

## Authoring and consumers

- Set `efficio_fill_mode` to `selection` on one native PowerPoint group.
- Set `efficio_fill_selection` to an object containing `selected_case_id`,
  `unselected_case_id`, and `items` (`item_id`, `label`, optional `instruction`).
- Reference a classification scheme with exactly those two cases using the
  existing `efficio_classification_scheme_id` tag.
- Mark each item shape or subgroup with its `efficio_selection_item_id`.
  Each declared item must resolve exactly once within the owner group; item
  subgroups cannot overlap. Unmarked decoration stays unchanged.
- The Template Editor must expose this mode, maintain the named item markers,
  and treat the owner as one component rather than initializing its items as
  independently rendered components. Consume generated SDK metadata.
- Slide Generator must validate item targets during import, render both selected
  and unselected items, and support the new exact schema in generation/repair.

The component output is `{"selected_ids":["germany","france"]}`. An empty
array deselects every declared item. Unknown IDs and duplicates are invalid.
Colors and target metadata remain private. Clients forward the supplied AI
payload and submit the returned component object without remapping it.

No automatic classification-to-selection migration is performed: grouping and
binary case meaning are authoring decisions. Existing templates opt in by being
updated and re-imported. No database or infrastructure migration is required.

## Verification

Local verification is limited to generated-contract consistency, static checks,
and focused content/normalization checks. Full local suites and Docker builds
are intentionally omitted for this release; the existing release workflow
remains the publication gate.
