# 0.6.1 — plain-text capacity migration correction

**Contracts package:** `0.6.1`

**Template contract revision:** `2` (unchanged)

**Contracts status:** ready to publish

**Release status:** publication pending

## Why this patch exists

The revision 1 to revision 2 text-capacity migration in `0.6.0` rejected a
legacy plain-text component when it still carried multi-item bounds or
`efficio_target_items`. Those values were valid authoring leftovers before the
plain-text single-item rule became explicit, so the migration must normalize
them instead of blocking the presentation upgrade.

## Completed behavior

For text components and rendered table cells whose existing text format is
`plain`, the migration now:

- keeps `efficio_text_format=plain` unchanged;
- keeps the existing sizing mode unchanged;
- writes `min_items=1` and `max_items=1`;
- removes `target_items`;
- performs the existing line-capacity conversion without changing the authored
  text format.

Every valid non-plain text format remains unchanged and keeps its applicable
item limits. Invalid or unsupported formats still fail clearly. No schema, tag,
component type, migration file, or template revision changed in this patch.

The TypeScript and Python migration planners implement the same behavior and
share regression fixtures for plain text and plain table cells.

## Consumer work

Consumers using the revision-2 migration planner should upgrade their exact
dependency from `0.6.0` to `0.6.1`. They must continue calling the public
migration planner and must not preprocess or duplicate this normalization.

The Template Editor additionally verifies linked component-template assignments
through its normal current-contract resolver after the SDK migrates their raw
legacy representation. This lets a shape preserve a valid local plain-format
override while inherited multi-item guidance is removed during resolution.
